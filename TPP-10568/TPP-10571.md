## Background

US Bank currently has a Swift Messaging Conversion Application Programming Interface (API) that is partially built — two Bank of New York Mellon message types have already been implemented in Java by the offshore team. This story extends that Application Programming Interface (API) to support the MT515 Trade Input message, which is the message used to submit trades to Fixed Income Clearing Corporation (FICC) Government Securities Division (GSD) in place of manual Real-Time Trade Matching (RTTM) web entry.

The MT515 message uses Society for Worldwide Interbank Financial Telecommunication (SWIFT)-standard (ISO 15022) formatting but is transmitted over Fixed Income Clearing Corporation (FICC)'s own proprietary Message Queue (MQ) network — not the SWIFT network. The Application Programming Interface (API) already handles this distinction for Bank of New York Mellon messages; the same pattern applies here with a different destination channel.

Fixed Income Clearing Corporation (FICC) uses three MT515 styles depending on the product:
- **Delivery Versus Payment (DVP)** — for repo and Delivery Versus Payment cash trades
- **General Collateral Finance (GCF)** — for General Collateral Finance repo trades
- **Centrally Cleared Institutional Triparty (CCIT)** — for Centrally Cleared Institutional Triparty trades

The specific styles required for US Bank's trade types must be confirmed (see open questions), but Delivery Versus Payment is the primary style to implement first given it covers Sheila's Delivery Versus Payment / Funding group and Money Center Trading.

Reference specification: `Kurt_info/gsd200_gsd_im_member_specs_comparison_io_2023.pdf`, pages 15–40 (MT515 format specifications).

## User Story

**As** Collateral Pledging Management System (CPMS),
**I need** the Swift Messaging Conversion Application Programming Interface (API) to accept trade details and return a correctly formatted MT515 text string,
**so that** the Message Queue (MQ) Application Programming Interface (API) can route it to Fixed Income Clearing Corporation (FICC) and replace manual Real-Time Trade Matching (RTTM) entry.

## Acceptance Criteria

- [ ] The Swift Messaging Conversion Application Programming Interface (API) exposes a new endpoint / method that accepts trade data and returns a valid MT515 message string
- [ ] Input parameters must cover all mandatory MT515 fields as identified in TPP-10569 (field mapping)
- [ ] MT515 message is built in correct ISO 15022 SWIFT format — block structure, field tags, and value formatting must conform to GSD200 specification
- [ ] Support MT515 **Delivery Versus Payment (DVP) style** for:
  - Repo transactions
  - Buy/Sell (Cash) transactions
- [ ] The Counterparty (Contra) Firm ID is retrieved via the lookup table built in TPP-10570 — the Application Programming Interface (API) does not accept a raw counterparty name
- [ ] Member's Firm ID is hardcoded as **9286** (US Bank National Association) — not passed as a parameter
- [ ] If any mandatory field is missing or invalid, the method returns a structured error — it does not return a partial message
- [ ] All field values are validated against Fixed Income Clearing Corporation (FICC) format rules before the message is assembled (data types, lengths, allowed values)
- [ ] MT515 message generation is logged with: trade reference number, timestamp, message type, and whether generation succeeded or failed
- [ ] Unit tests cover: successful Delivery Versus Payment Repo message, successful Delivery Versus Payment Buy/Sell message, missing mandatory field error, invalid Contra Firm ID error

## Technical Notes

- The existing Swift Messaging Conversion Application Programming Interface (API) is written in Java — MT515 support should follow the same patterns already established for Bank of New York Mellon message types
- The MT515 message structure uses ISO 15022 block/tag format. Key blocks:
  - Block 1 — Basic header
  - Block 2 — Application header (includes message type MT515)
  - Block 4 — Text block containing the trade fields (tagged data)
- The GSD200 document defines three sequences within MT515: Sequence A (General Information), Sequence B (Trade Details), Sequence C (Financial Instrument). Mandatory fields are spread across all three sequences.
- The output of this method is a plain text string — it is passed directly to the Message Queue (MQ) Application Programming Interface (API) (TPP-10573) for routing. No additional transformation is needed after this step.
