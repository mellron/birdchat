## Background

US Bank currently has a working process for General Collateral Finance (GCF) trades where Vin downloads a spreadsheet from Bank of New York Mellon's AccessEdge system and uses the Collateral Pledging Management System (CPMS) bulk upload function to load those trades into Collateral Pledging Management System (CPMS). This process is in User Acceptance Testing (UAT) — not yet in production.

This story extends that same process to cover **Delivery Versus Payment (DVP) trades** — Sheila's primary trade type. The result is that Delivery Versus Payment trade data flows from Bank of New York Mellon's existing download capability into Collateral Pledging Management System (CPMS), where it will be picked up by the new Fixed Income Clearing Corporation (FICC) submission user interface (TPP-10575).

**Constraint**: No modifications to Bank of New York Mellon systems or screens are permitted. This story must work entirely with Bank of New York Mellon's existing download/export functionality as-is.

---

## User Story

**As** Sheila's Delivery Versus Payment / Funding group,
**I need** Delivery Versus Payment trade data from Bank of New York Mellon's AccessEdge download to flow into Collateral Pledging Management System (CPMS),
**so that** trades are ready for review and Fixed Income Clearing Corporation (FICC) submission on the new Collateral Pledging Management System (CPMS) screen without manual re-entry.

---

## Acceptance Criteria

- [ ] Identify the exact Bank of New York Mellon AccessEdge download format for Delivery Versus Payment trades — confirm column names, data types, and file format (likely spreadsheet / comma-separated values)
- [ ] Confirm the download contains all fields required by MT515 for Delivery Versus Payment trades (cross-reference with TPP-10569 field mapping)
- [ ] Document any fields present in the download that are **not** in the current General Collateral Finance bulk upload process — these are net-new fields to handle
- [ ] Extend the Collateral Pledging Management System (CPMS) bulk upload function to accept Delivery Versus Payment trade data:
  - Map Bank of New York Mellon download columns to Collateral Pledging Management System (CPMS) trade record fields
  - Validate mandatory fields on import — reject rows with missing required data with a clear error message
  - Handle duplicate detection — do not create duplicate trade records if the same download is processed twice
- [ ] Imported Delivery Versus Payment trades are stored in Collateral Pledging Management System (CPMS) with status **"Pending Fixed Income Clearing Corporation (FICC) Submission"** so the new user interface (TPP-10575) can display them
- [ ] Import results are logged: number of records processed, number accepted, number rejected, rejection reasons
- [ ] The process works for both manual trigger (Vin or Sheila runs the upload) and is designed to support future automation/scheduling if needed

---

## Open Questions

- Does the Bank of New York Mellon AccessEdge download for Delivery Versus Payment trades use the same file format as the General Collateral Finance download, or a different format?
- Who triggers the download today — Vin only, or does Sheila also do it? Who should own this step going forward?
- Should the download/upload be triggered on a schedule (e.g., every morning) or remain manual?
- Does the existing General Collateral Finance bulk upload process need to remain separate, or can it be merged with the Delivery Versus Payment process into a single import?
