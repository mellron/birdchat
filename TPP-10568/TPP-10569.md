## Background

Before any code can be written to automate trade submission to Fixed Income Clearing Corporation (FICC), we need to know exactly which data fields are available in our source systems and which are gaps.

The Fixed Income Clearing Corporation (FICC) Government Securities Division (GSD) Interactive Messaging (IM) specification (GSD200, Appendix A) defines the mandatory fields required in every MT515 Trade Input message. There are two sets of mandatory fields — one for Buy/Sell (Cash) transactions and one for Repo transactions.

US Bank's candidate source systems are:
- **Intrader** — internal system where Bloomberg Trade Order Management System (TOMS) positions are recorded
- **Collateral Pledging Management System (CPMS)** — internal collateral tracking system
- **Bloomberg Trade Order Management System (TOMS)** — where Money Center and Investment Portfolio trades are originally booked

Reference document: `Kurt_info/gsd200_gsd_im_member_specs_comparison_io_2023.pdf`, Appendix A (page 107)

## Acceptance Criteria

- [ ] For each mandatory field in both trade types, document: source system, exact field/column name, data type, and any transformation needed to match Fixed Income Clearing Corporation (FICC) expected format
- [ ] Identify every field that is a **gap** — not available in any current source system
- [ ] For calculated fields, document the calculation formula
- [ ] For fields with code/value mapping (e.g., Transaction Type), document the mapping table between source system values and Fixed Income Clearing Corporation (FICC) expected values
- [ ] Produce a summary table: field name | source | available (yes / no / calculated) | gap notes
- [ ] Flag any fields where format conversion is needed (e.g., date formats, decimal precision, currency)
