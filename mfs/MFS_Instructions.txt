Introduction
The Connect: Direct Passthrough (CDPT) server environment is a shared service provided by Managed File Services (MFS) that can be used to perform batch file transfers. The environment is highly-resilient and comprised of a group of Connect: Direct (CD) servers running Windows Server. In most cases this environment can be used for Connect: Direct file transfers without the need to install the Connect: Direct application on your application servers.
The following endpoints are supported by the CDPT environment:
•
On-Premise/Cloud Connect: Direct Servers: Other application servers or mainframes that have Connect: Direct installed on them.
•
Sterling File Gateway: This system is used to communicate with external trading partners over VPN or the Internet (using various supported protocols, including Connect: Direct).
•
On-Premise File Shares: Any shared folder or NAS that is accessible via a UNC path using the SMB protocol.
•
UNIX File Systems: Via multi-protocol NAS (NFS + CIFS).
•
Cloud File Shares: Azure Files and Amazon FSx is supported using a UNC path via the SMB protocol.
•
NOTE: Cloud object storage (S3, Blob, etc.) is not supported at this time.
The onboarding of file transfers using the CDPT is designed for self-service. MFS does not need to make any changes to set up a new CDPT file transfer, with one exception: If an endpoint is a new CD server that is not yet configured to communicate with the CDPT environment, MFS will need to set up that connection first.
This document outlines the steps required to onboard new file transfers using CDPT. All access requests must be completed by the team that will own the file transfer. In the event of an audit that team would be in the best position to determine if access is still needed.
The following sections describe the prerequisites for each of the fore-mentioned endpoints. Lastly, please review the Automation section. Once all requirements have been met and automation has been set up the file transfers can commence.
To request assistance from MFS please submit a consultation request
Data Storage
As the name suggests the CD Passthrough environment does not store data in transit for any period of time, it simply passes it from source to destination. The owners of the source and destination endpoints are responsible for meeting any PCI requirements related to data at rest. CDPT is capable of writing and reading to/from enclaved systems and NAS, although new firewall rules may be required.

Connect: Direct Application Servers (On-Premise or Cloud)
If both endpoints are Connect: Direct servers it is not necessary to use the CDPT environment. The two endpoints can communicate directly with each other using Connect: Direct. To request assistance from MFS with a server-to-server Connect: Direct transfer please submit a consultation request.
If an endpoint requires a new installation of Connect: Direct please submit a consultation request.
The business acquiring the new installation will be responsible for any costs associated with acquiring the new Connect: Direct licensing.
New installations will only be performed on Windows Server (2019 or higher) or RHEL 8 (Linux). The server or VM can be located on-premise or in the cloud. Note: Container installations are not supported at this time.

UNIX File Systems
In the past the requirement to perform a Connect: Direct transfer to or from a UNIX/Linux system automatically meant the requirement for the Connect: Direct application to be installed on the Linux system. Now this can be accomplished with multi-protocol NAS (NFS + CIFS). The storage group will create a NAS share that can be accessed via UNC path on Windows systems, and it will also be mounted on the requested Linux system(s) as a new file system.
Note: The account that owns the file share on the Linux system(s) must be a domain account. If the server does not have any domain accounts connected you will be required to have one created and granted access (Application Account request) to the server before the share can be mounted.

Automation
Once the endpoints have been configured, access has been established and any other pre-requisites have been completed, you must configure automation that will execute the file transfers through the CDPT environment on a schedule, using a file watcher, etc. Autosys is the most widely used scheduler at U.S. Bank / Elavon but there are other options as well. For additional information regarding any of the options below besides Autosys, please submit a MFS consultation request
•
Autosys: Enterprise scheduler. Most Connect: Direct file transfers are initiated via Autosys jobs.
•
CA7: File transfers initiated on mainframes will typically use CA7 instead of Autosys. Contact your mainframe application developer for more information.
•
Microsoft .NET SDK: If your application uses .NET MFS can provide an SDK from IBM for interfacing with Connect: Direct on the passthrough servers. MFS does not provide support for the SDK.
•
Java API: MFS can provide a JAR file from IBM that can be installed on Windows or Linux systems IBM provides limited documentation which we will pass along to you as needed.
•
Web Services: Newly available from MFS is the ability to utilize Connect: Direct Web Services to use REST API’s for submitting CD processes and monitoring their status. At present MFS does not have documentation for this service beyond what is provided by IBM, so it is to be used “as it”.
Autosys
Autosys jobs can be run on a schedule or based on the appearance of a new file in a specified directory (file watcher). It is preferred to use a file watcher. Their purpose is to execute a batch script on the CDPT server that submits a file transfer process to Connect: Direct. The information needed for your file transfer is passed via script arguments. There are a small number of different scripts that should be used based on the platform of the destination Connect: Direct server.
Navigate to https://autosys-jobs.us.bank-dns.com for links to Autosys sites, documentation, etc.
The following are template Autosys jobs. Replace the highlighted text with appropriate values for your file transfer using the guide below. Use the table below the sample jobs to determine the required parameters for each of the available Connect: Direct batch scripts.
